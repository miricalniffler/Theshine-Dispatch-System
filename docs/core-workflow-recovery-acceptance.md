# 核心业务恢复验收记录

日期：2026-10-16

## 已修复的阻塞点

- 订单详情读取不再等待泰文 AI 翻译；AI 只会在运营人员明确点击分析时调用。
- 订单详情与操作记录读取只使用稳定的司机资料字段。测试库尚未执行可选字段升级时，订单不会再被误显示为不存在。
- 详情页遇到网络、鉴权或服务错误时会显示原因、重试和返回入口，不会永久显示“正在读取订单”。备注和取消入口会随订单正常读取恢复可见。
- 编辑、飞书取消与 i'way 回传确认均以数据库内的当前订单状态为准，避免取消订单被后续操作覆盖。
- i'way 预览、复制和确认接口对空请求、异常服务响应返回 JSON；页面不会再把 HTML/空响应误报为 `Unexpected end of JSON input`。
- esforty 紧凑订单号支持前导 `#`、非断行空格、连字符和更多分组形式；车型支持常用缩写及 Plus 标记。
- 未配置访问口令时，站点改为拒绝访问而非意外放行。

## 2026-10-16 隔离环境真实浏览器验收

- 已使用 Prisma Dev 在本机创建命名为 `theshine-pr12-e2e` 的空 PostgreSQL 临时库，并对该库成功执行全部四个 migration；没有连接、读取或写入远程数据库。
- 已以脱敏 esforty 紧凑文本调用本机测试站点的解析接口，得到成功响应及 `esforty_compact_list` 格式识别结果；AI Key、飞书连接和真实消息均未配置。
- 发现并修复一个实际流程断点：复制车队派单文本后，页面现在会提供明确的“我已派单，确认状态”操作。只有运营人员确认已自行发送后，订单才会进入司机资料流程；系统不会代发消息。
- 隔离库使用的本机 Prisma Dev 连接代理需要 `pgbouncer=true`。未加该参数时，接口会返回 PostgreSQL `prepared statement "s0" already exists`；这是测试连接配置问题，不是“无订单”的业务结果。修正后，解析接口和页面均正常返回。
- 修复了订单详情的成功提示读取层级：接口把 `updatedFields` 包在 `data` 内，页面此前误显示“没有需要保存的修改”，实际修改虽已入库。
- 修复了车队资料保存后回传预览被刷新操作清空的问题；现在刷新候选订单不会清掉待复制的同日回传文本，只有切换日期才会清空旧批次。
- E2E 写入用例固定为单个桌面浏览器项目，并让两笔订单的数字订单号也彼此不同，避免不同设备项目或订单号规范化造成并发串单。

### 真实浏览器结果（隔离本机库）

以下命令在本机隔离库及本机测试站点执行，结果为 **3 通过，0 失败**：

```text

E2E_TEAM_ACCESS_TOKEN=（仅本机测试令牌） \
npx playwright test tests/core-workflow-e2e.spec.ts --project=desktop-chrome --timeout=20000
```

已由真实 Chromium 浏览器完成、并由页面状态及后端写入共同验证的步骤：

1. 粘贴脱敏 esforty 订单、识别字段、保存，并在订单工作台按订单号找到订单。
2. 打开详情，修改“其他备注”并保存；添加异常备注，刷新页面后在操作记录中仍可查看。
3. 取消该订单；页面显示已取消且编辑表单不可用。
4. 导入另一笔订单，生成并复制车队派单文本后，由测试操作明确确认派单。
5. 在当前“车队回复与 i’way 回传”页面录入脱敏司机资料，生成 i’way 预览并执行浏览器复制。
6. 在另一浏览器页取消该订单；回到原回传页确认旧批次时，页面显示“批次中有订单已取消或状态已变化，未完成回传。请重新生成。”，没有把订单标记为已回传。
7. 飞书同步状态接口在禁用真实飞书连接的隔离环境返回本地计划同步模式；订单读取接口能查到已取消的测试订单。
