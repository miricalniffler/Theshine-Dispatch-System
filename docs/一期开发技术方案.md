# 接送机发单平台一期：开发技术方案

## 已确认的产品决策

- 曼谷和苏梅的派单订单正文完全统一，使用 `templates.dispatch`。
- 批量派单按同一服务日、同一城市、同一车队分组；批次结尾才按城市读取 YAML。
- 同一服务日的曼谷和苏梅订单可以合并为一条 i’way 回传。
- 微信和 WhatsApp 只生成和复制文本，发送与确认仍由人工完成。
- 派单、回传、校验、电话和车型规则的唯一来源是 `config/business-rules.yaml`。

## 结构

- `src/app`：页面和 API 入口。
- `src/features`：按业务模块组织的界面、服务和测试。
- `src/lib/rules`：规则读取、验证、模板渲染和版本快照。
- `config/business-rules.yaml`：当前可发布的业务规则。
- `docs/modules`：可独立并行开发的工作说明。

## 统一约定

- API 成功响应：`{ data }`；失败响应：`{ error: { code, message, fields? } }`。
- 所有“生成”记录保存规则版本和文本快照；历史快照不可覆盖。
- 状态：`PENDING_REVIEW`、`PENDING_DISPATCH`、`DISPATCHED_AWAITING_DRIVER`、`PENDING_IWAY_RETURN`、`COMPLETED`、`EXCEPTION`。
- 共享契约变更先修改 `docs/API-CONTRACT.md`，再修改调用模块。

详见 [模块开发说明](./modules/README.md)。
