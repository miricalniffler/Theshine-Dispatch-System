# M0 数据字典与规则引擎

## 持久化约定

- 开发环境使用 SQLite，连接地址写在 `DATABASE_URL`；部署时仅需将 Prisma 的连接改为 PostgreSQL 并执行迁移。
- `Order` 是唯一订单主记录；`serviceDate` 是曼谷时区的 `YYYY-MM-DD`，用于筛选、分组和批量规则。
- 每个 `DispatchBatch` 与 `IwayReturnBatch` 都保存 `ruleVersion` 和 `contentSnapshot`，规则改版不会改变历史文本。
- 状态用字符串保存，允许一期后续增加状态而无需数据库枚举迁移。

## 关键数据字段

| 表 | 关键字段 | 用途 |
|---|---|---|
| `Order` | `platformOrderNumber`、`city`、`fleetId`、`serviceDate`、`status` | 订单识别、派单分组和状态流转 |
| `DriverDetail` | 司机、规范化电话、车型、车牌 | i’way 回传前的必填资料 |
| `DispatchBatch` | 城市、车队、服务日、规则版本、文本快照 | 人工发送车队派单的可追溯记录 |
| `IwayReturnBatch` | 服务日、规则版本、文本快照 | 同服务日曼谷/苏梅合并回传记录 |
| `RuleVersion` | YAML 全文、版本、是否现行 | 规则发布历史 |
| `ActivityLog` | 订单、动作、操作者、元数据 | 导入、复制、确认等审计记录 |

## 规则引擎

规则只从 `config/business-rules.yaml` 加载。支持的模板写法为：

- `{{field}}`：输出字段。
- `{{field|default('none')}}`：为空时使用默认值。
- `{{field|prefix(' ')}}`：非空时加前缀。
- `{{field|omit_if_empty}}`：为空时整段不输出。

`validateRequiredFields()` 根据 `before_dispatch` 或 `before_iway_return` 返回缺失字段；`normalizeThailandPhone()`、`normalizeVehicleModel()` 分别按 YAML 的电话和车型规则转换。页面和业务接口不得自行硬编码这些判断。
