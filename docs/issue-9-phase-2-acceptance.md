# Issue #9 第二阶段验收报告

## 本次范围

- 车辆档案：按保留泰文字母的规范化车牌查询；保留原车牌、品牌、车型、车辆类别、来源、人工确认状态、历史记录及多司机关联。
- 司机姓名来源：区分人工确认、截图泰语转写、系统临时生成；系统临时名在 i’way 预览阶段会被明确拦截。
- 截图识别：提供不落库的结构化识别接口，返回订单、行程、乘客、行李、司机、电话和车牌字段；字段看不清时返回空值，不补造事实。
- 模型策略：截图识别先尝试 GLM（30 秒），失败后才调用 Qwen；DeepSeek 不参与默认回退。`AI_VISION_MOCK_MODE=true` 会返回带“模拟”标识的结果且不调用真实服务。

## 审查修复（PR #11）

- 取消竞态：保存司机资料和确认 i’way 回传均改为事务内条件更新。取消订单不能被写回可回传/已完成状态；状态变化会返回冲突而不是继续写入。
- 档案覆盖：公开接口不再接收 `source` 或覆盖开关；已人工确认的档案不会被普通请求改写。原车牌写法或车型不一致时保留原值，并留下“档案冲突”历史记录。
- 姓名来源：AI 临时名、截图转写名都会保持待核对状态；只有操作员勾选“已核对”后，服务端才标为人工确认并允许回传。
- 接口防护：车辆档案读写和截图识别均增加 API 层登录校验，不能只依赖页面跳转保护。

## 2026-10-16 Preview 订单可见性故障修复

- 根因判断：Preview 的数据库连接变量已配置，但本分支新增的 `DriverDetail` 字段需要 migration；订单工作台此前读取完整司机资料，若测试库未升级该新列会使整个订单查询失败。前端又把非成功响应静默当作空数组，因而出现“订单全部消失”的假象。
- 修复：订单列表仅选择当前页面需要的既有司机字段，不再因新增可选字段缺列而阻断旧订单显示；接口失败返回明确 503，两个订单页面显示错误及重试按钮；订单号关键词查询覆盖日期窗口；“全为 0”的飞书同步提示明确说明这不代表删除旧订单。
- 安全边界：未读取数据库连接串或密钥，未连接、迁移或写入任何数据库。由于未获安全的只读数据库审计通道，尚不能以聚合查询直接确认旧订单行数；待 Preview 登录后即可验证旧订单恢复显示。
